# 需求记录与跟踪规则

## 目的
确保每次用户输入的需求都被完整记录，包括对需求的理解和实际拆分结果，便于后续跟踪、回溯和验证。

## 记录时机
每次用户输入新需求时，必须执行以下步骤：
1. 完整记录原始需求
2. 记录对需求的理解
3. 拆分任务
4. 保存到 `src/docs/requirements/` 目录

## 记录文件结构

### 文件命名规范
```
YYYY-MM-DD-需求简短描述.md
```
例如：`2026-03-21-到发盯控页面优化需求.md`

### 文档模板

```markdown
# 需求记录 - [日期]

## 1. 原始需求
[完整复制用户的原始需求]

## 2. 需求理解
### 2.1 核心目标
[简要描述需求的核心目标]

### 2.2 关键要点
- [要点1]
- [要点2]
- ...

## 3. 任务拆分
### 3.1 任务清单
- [ ] 任务1：[描述]
  - 优先级：P0/P1/P2
  - 依赖：[依赖的任务ID]
  - 验收标准：[验收标准]

- [ ] 任务2：[描述]
  - 优先级：P0/P1/P2
  - 依赖：[依赖的任务ID]
  - 验收标准：[验收标准]

...

## 4. 实施计划
[详细的实施计划，如适用]

## 5. 变更记录
- [日期]：[变更内容]

## 6. 验收结果
- [ ] 功能验收：通过/未通过
- [ ] 视觉验收：通过/未通过
- [ ] 代码验收：通过/未通过
```

## 目录结构
```
src/docs/
└── requirements/
    ├── 2026-03-21-到发盯控页面优化需求.md
    ├── 2026-03-20-其他需求.md
    └── ...
```

## 执行流程
1. 收到用户需求
2. 在 `src/docs/requirements/` 目录下创建新的需求记录文件
3. 完整填写模板内容
4. 与用户确认理解无误后开始实施
5. 实施完成后更新验收结果

## 注意事项
- 原始需求必须完整保留用户原文
- 需求理解要简洁明了，抓住关键点
- 任务拆分要具体、可执行、可验收
- 优先级定义：
  - P0：必须完成，核心功能
  - P1：重要功能，应该完成
  - P2：优化项，可以延后
