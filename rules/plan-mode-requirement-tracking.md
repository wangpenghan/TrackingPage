# /plan 模式需求自动记录规则

## 目的

在 /plan 模式下，每次用户输入的需求都被自动记录、归档，并在同一个文件中追踪需求的新增、变化和版本信息，确保需求的可追溯性和完整性。

## 触发条件

当用户输入 `/plan` 命令并附带需求描述时，自动执行需求记录流程。

## 记录文件位置

```
src/docs/requirements/requirement-registry.md
```

所有 /plan 模式下的需求都记录在同一个文件中，通过版本化进行管理。

## 自动记录流程

### 1. 检测 /plan 模式
当检测到用户输入 `/plan` 命令时，自动启动需求记录流程。

### 2. 需求识别与提取
- 提取用户需求的核心内容
- 判断是否为全新需求或已有需求的变更

### 3. 需求ID分配规则
- 格式：`REQ-XXX`（XXX 为三位序号，从 001 开始）
- 同一需求的不同版本使用相同 ID

### 4. 版本号管理规则
- **v1.0**: 初始版本
- **v1.1, v1.2...**: 小版本变更（补充说明、细化需求）
- **v2.0**: 重大变更（需求方向调整、核心功能变化）

### 5. 状态管理
- **活跃**: 需求正在处理中或等待实现
- **已归档**: 需求已实现或被搁置
- **已实现**: 需求已完成开发并通过验收

## 变更记录格式

当同一需求发生变更时，在需求条目下追加新的版本记录：

```markdown
### 版本变更记录

#### v1.1 (YYYY-MM-DD)
- **变更类型**: 修改
- **变更内容**: [描述具体修改内容]
- **变更原因**: [描述变更原因]
```

## 执行时机

1. **需求新增时**: 创建新的需求条目，版本为 v1.0
2. **需求变更时**: 在已有需求下追加新的版本记录
3. **需求确认时**: 更新需求状态和验收信息

## 归档规则

当需求实现完成后：
1. 更新需求状态为"已实现"
2. 记录验收信息和验收日期
3. 保留完整的需求历史记录

## 注意事项

- 原始需求内容必须完整保留
- 每次变更必须记录变更类型、变更内容和变更原因
- 保持需求索引与实际内容同步更新
- 关联的计划文件路径需要同步记录
