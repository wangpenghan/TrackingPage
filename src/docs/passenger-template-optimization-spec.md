# 客运模板功能与 UI 优化设计方案

## 1. 背景与目标
针对客运模板在实际使用中反馈的视觉语义歧义、无效数据识别难、编辑体验不佳以及时间展示不规范等问题，本方案旨在重构页面的状态视觉体系，并深化确认按钮的业务逻辑，确保数据管理的严谨性与交互的直观性。

## 2. 状态视觉体系重构 (解决颜色歧义)

### 2.1 颜色语义重新定义
统一页面内所有标签、边框及按钮的颜色语义，移除顶部筛选按钮与数据状态之间的色彩关联。

| 业务状态 | 语义含义 | 建议色值 (Indigo 系) | UI 应用位置 |
| :--- | :--- | :--- | :--- |
| **未确认** | 原始导入数据，需人工核对 | **红色 (#EF4444)** | 卡片左侧条、确认按钮、状态标签 |
| **未同步** | 数据已确认，待推送到基本计划 | **橙色 (#F59E0B)** | 同步标签、同步按钮 |
| **已完成** | 已确认且已完成同步 | **绿色 (#10B981)** | 状态标签、完成图标 |
| **无效数据** | `isValid: false` 的停开/作废车次 | **灰色 (#9CA3AF)** | 卡片背景、车次号删除线、置灰按钮 |

### 2.2 筛选区域优化
*   **筛选按钮**：不再使用红/橙色区分，统一使用 Indigo 主色或浅灰色。仅通过填充色（激活）和边框色（未激活）来区分状态，避免干扰用户对数据状态的判断。

## 3. 无效数据显性化处理

### 3.1 列表呈现
*   **视觉降权**：无效数据的整行卡片应用 `opacity: 0.6` 的透明度，并使用浅灰色背景。
*   **显著标记**：在车次号（TrainNo）前增加 `[无效]` 标签，车次号本身添加删除线效果。
*   **状态冲突处理**：即使在详情中某些字段显示有效，但在列表中必须严格遵循 `isValid` 字段进行全局标记，确保调度员一眼看出该计划已失效。

## 4. 编辑页面 (EditDrawer) 交互优化

### 4.1 时间控件宽度调整
*   **宽度扩充**：将所有涉及时间输入（到达、发车、始发、终到）的控件容器宽度增加 **25%**。
*   **展示优化**：确保在各语种或高 DPI 屏幕下，`HH:mm` 格式的时间字符及其占位符不会被水平裁剪。
*   **间距微调**：增加 Input 内部的 `padding-right`，为可能出现的晚点标记或清除按钮预留空间。

## 5. 列表时间与晚点展示逻辑

### 5.1 晚点信息重构
解决晚点信息导致的排版换行问题，采用垂直布局：

*   **布局位置**：晚点信息统一显示在对应时间文字的**正下方**。
*   **展示规则 (Merging Logic)**：
    *   **到发一致**：若到达晚点与发车晚点数值相同，合并显示为一行：`晚点 +{delay} min`。
    *   **到发不一**：分别显示两行：`到晚 +{arr} min` / `发晚 +{dep} min`。
*   **视觉样式**：
    *   使用 `11px` 细体字。
    *   正数（晚点）使用橙色 (#F59E0B)，负数（早到）使用蓝色 (#3B82F6)。

## 6. 确认按钮业务逻辑设计

### 6.1 核心流程：验证 -> 提示 -> 确认
确认按钮不再是简单的开关，而是一套数据准入机制。

#### A. 强校验 (Blocking)
点击确认时，系统必须检查以下项，若不通过则禁止确认：
*   **完整性**：股道、站台、检票口（始发/途径）、出站口（终到/途径）不能为空。
*   **一致性**：到达时间必须早于发车时间（途径）；进站开检必须早于停检。
*   **错误反馈**：以列表形式展示所有错误，点击错误项可自动定位并高亮编辑区对应的输入框。

#### B. 弱提示 (Warning)
*   对于担当局、列车定员等非必填但重要的项，若缺失则弹出对话框：“[担当局]等信息未填写，是否确认该模板？”

#### C. 确认后效应
*   **状态锁定**：字段 `confirmed` 设为 `true`。
*   **自动审计**：自动记录当前操作人为 `operator`，当前服务器时间为 `operateTime`。
*   **重置机制**：已确认的模板若被再次编辑并保存关键字段，系统需提示并自动将其重置为“未确认”状态。

## 7. 实现建议
1.  **CSS 变量**：将 Indigo、红、橙、绿、灰定义为全局 CSS 变量，确保颜色的一致性。
2.  **验证 Hook**：抽象 `useTemplateValidation` 钩子，同时服务于编辑页面和批量确认功能。
3.  **列表原子化**：重构 `TimeDisplay` 组件，内部封装到发晚点合并逻辑。
