# 运行规律组件优化设计方案

**版本：** v1.0  
**日期：** 2026-05-08  
**适用模块：** 客运模板 / 编辑抽屉 / 运行规律

---

## 1. 现状问题

| 编号 | 问题描述 | 影响 |
| :--- | :--- | :--- |
| P1 | 日历未按起始有效期截断，有效期前的日期仍然高亮显示为开行 | 视觉误导，用户误以为有效期前也会开行 |
| P2 | 隔日开行缺少「从哪天起算」配置，无法区分当日还是次日起步 | 隔日规律不准确，无法精确生成运行计划 |
| P3 | 规律开行缺少周期单位配置，仅能按周中星期设置，不支持按月或自定义 N 天周期 | 无法表达「每月某几天」「每 N 天中某天开行」等真实业务需求 |

---

## 2. 优化方案

### 2.1 日历截断：按有效期高亮

**规则：**
- 起始有效期前的日期：即使满足开行规律，也**不高亮**，显示为灰色，表示该日不开行。
- 终止有效期后的日期：同样不高亮。
- 有效期内且满足开行规律的日期：正常高亮。

**视觉区分：**

| 日期状态 | 高亮颜色 | 说明 |
| :--- | :--- | :--- |
| 有效期内 · 开行日 | 蓝色（`#5e6ad2`）| 正常开行 |
| 有效期外 · 理论开行日 | 灰色斜纹或浅灰（`#E5E7EB`）| 不在有效范围，不开行 |
| 非开行日 | 白色 | 不开行 |
| 今日 | 边框标记（`border-indigo-400`）| 当前日期参考 |

**`isDayHighlighted` 逻辑修改（伪代码）：**
```ts
const isDayHighlighted = (day: number | null): 'active' | 'inactive' | 'none' => {
  if (day === null) return 'none'
  const date = new Date(year, month, day)

  // 判断是否满足开行规律（已有逻辑）
  const meetsRule = checkOperationRule(date, formData)
  if (!meetsRule) return 'none'

  // 判断是否在有效期内
  const validStart = formData.validStart ? new Date(formData.validStart) : null
  const validEnd   = formData.validEnd   ? new Date(formData.validEnd)   : null
  const inRange =
    (!validStart || date >= validStart) &&
    (!validEnd   || date <= validEnd)

  return inRange ? 'active' : 'inactive'
}
```

### 2.2 隔日开行：补充起始基准配置

**业务背景：**  
隔日开行的运行周期为 2 天。但「从哪一天算第 1 天」会影响整个排班结果：
- 若起始有效期为 4 月 17 日（周四），选择「当日开行」，则 4/17、4/19、4/21… 开行
- 若选择「次日开行」，则 4/18、4/20、4/22… 开行

**新增配置项：隔日起算基准**

| 选项 | 说明 |
| :--- | :--- |
| **从起始日开行**（默认）| 第 1 天 = 起始有效期当日，奇数天（第 1、3、5…天）开行 |
| **从起始次日开行** | 第 1 天 = 起始有效期次日，偶数天（第 2、4、6…天）开行 |

**UI 交互：**
- 选择「隔日开行」后，左侧配置区出现单选按钮组：
  ```
  [●] 从开行日期当日起
  [○] 从开行日期次日起
  ```
- 切换选项后，右侧日历实时更新高亮日期。

**数据字段建议：**
```ts
alternateStartOffset: 0 | 1   // 0 = 当日起, 1 = 次日起
```

**计算逻辑（伪代码）：**
```ts
const isAlternateDayActive = (date: Date, startDate: Date, offset: 0 | 1): boolean => {
  const diffDays = Math.floor((date - startDate) / 86400000)
  return (diffDays + offset) % 2 === 0
}
```

### 2.3 规律开行：补充周期单位与配置

**现状：** 规律开行目前仅支持按「星期几」配置（位掩码），本质是以 7 天为固定周期。

**优化后支持三种周期模式：**

#### 模式 A：按周（7天周期）—— 保留现有逻辑
用户勾选每周的哪几天开行（星期一 ~ 星期日）。
- 适用场景：工作日开行、周末加班车等。

#### 模式 B：按月（自然月周期）
用户勾选每月的哪几号开行（1 ~ 31，若当月无该日则跳过）。
- 适用场景：每月 1 日、15 日开行的特定计划。
- UI：类似日历的月视图，可多选日期格。

#### 模式 C：自定义 N 天周期
用户设定一个周期长度 N（2~30天），并配置周期内的哪几天开行。
- 示例：周期 = 5 天，第 1、3 天开行，则每 5 天中，第 1、3 天跑车。
- 适用场景：复杂的值班制开行规律。
- UI：横向排列 N 个格子（每格代表周期内第 X 天），点击格子切换开/不开。

## 3. 数据模型变更

在 `TemplateData` 中扩展字段（保持向后兼容，旧数据视为按周模式）：

```ts
interface OperationRule {
  // 运行类型
  type: 'daily' | 'alternate' | 'scheduled'

  // 隔日开行配置
  alternateOffset?: 0 | 1          // 0 = 当日起, 1 = 次日起

  // 规律开行配置
  scheduleMode?: 'weekly' | 'monthly' | 'custom'
  weeklyMask?: number              // 位掩码，bit0=周一…bit6=周日（原 rule 字段）
  monthlyDays?: number[]           // 月内日期列表，如 [1, 15]
  customCycle?: number             // 自定义周期长度（天）
  customActiveDays?: number[]      // 周期内开行的天序，如 [1, 3]（从 1 起）
}
```
