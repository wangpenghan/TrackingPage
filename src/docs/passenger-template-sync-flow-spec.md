# 客运模板同步作业流程优化设计方案

**版本：** v1.0  
**日期：** 2026-05-08  
**适用模块：** 客运模板 / 同步至基本计划

---

## 1. 现状问题

| 编号 | 问题描述 | 影响 |
| :--- | :--- | :--- |
| P1 | 页面缺少独立的「同步客运模板」入口按钮 | 用户操作路径不明，依赖隐藏的行内按钮 |
| P2 | 同步前用户无法预知哪些车次满足同步条件 | 盲目操作，不知道哪些会被同步 |
| P3 | 同步执行后仅后台日志记录结果，前端无任何反馈 | 同步失败无感知，需事后翻日志排查 |
| P4 | 同步失败时用户无法快速定位问题车次并修复 | 问题发现慢，修复链路长 |
| P5 | 批量同步无撤销/重试机制 | 出错后只能重新全量操作 |

---

## 2. 设计目标

1. **可预知**：同步前告知用户本次将同步哪些车次，不满足条件的原因是什么。
2. **可观测**：同步执行过程和结果在页面内实时呈现，不依赖后台日志。
3. **可修复**：同步失败的车次能直接从结果页面跳转编辑，快速完成修复闭环。
4. **可重试**：对失败的车次支持单独重试，无需全量重新同步。

---

## 3. 业务规则

### 3.1 同步条件（车次必须同时满足）
- `confirmed === true`（已确认）
- `synced === false`（未同步）
- `isValid === true`（数据有效）

### 3.2 不满足时的排除原因分类
| 排除原因 | 说明 |
| :--- | :--- |
| **未确认** | 数据尚未经过人工审核确认 |
| **已同步** | 该车次本次同步周期内已推送完成 |
| **数据无效** | `isValid: false`，车次已停开或作废 |

## 4. 交互流程设计

### 4.1 整体流程图

```
用户点击「同步客运模板」
        │
        ▼
   ┌─────────────────┐
   │  同步预检弹窗    │  ← 分为「可同步」与「不可同步」两个分区
   │  展示本次分组    │
   └─────────────────┘
        │
   用户确认执行
        │
        ▼
   ┌─────────────────┐
   │  同步执行中     │  ← 逐条显示进度条，每条有状态指示
   └─────────────────┘
        │
        ▼
   ┌─────────────────┐
   │  同步结果汇总   │  ← 成功 / 失败 / 跳过 三栏汇总
   └─────────────────┘
        │
   失败车次 → 一键跳转编辑修复
   成功车次 → 关闭弹窗，列表状态自动刷新
```

## 5. 各环节详细设计

### 5.1 入口按钮

**位置：** 工具栏右侧，与「导入」「导出」「添加」并排，优先级最高，放最右。

**按钮样式：**
- 常规态：Indigo 主色填充按钮（`bg-indigo-600`），图标使用 `ArrowUpFromLine` 或 `RefreshCw`。
- 角标：按钮上方右角显示可同步车次数量的红色角标，例如 `3`，数量为 0 时不显示角标。

```
[导入]  [导出]  [添加]  [同步客运模板 ³]
```

---

### 5.2 同步预检弹窗（Modal）

点击按钮后弹出，弹窗分为两个区域：

#### 区域 A：本次可同步车次（绿色边框）
- 列表展示满足条件的所有车次
- 每条显示：车次号、类型（始发/途径/终到）、到发时间、股道
- 顶部注明数量：`共 N 条车次将被同步`

#### 区域 B：本次不可同步车次（灰色/红色边框）
- 列表展示被排除的车次及具体原因
- 每条显示：车次号、排除原因标签（未确认 / 已同步 / 数据无效）
- 顶部注明数量：`共 M 条车次被跳过`

#### 弹窗底部操作
| 按钮 | 行为 |
| :--- | :--- |
| **取消** | 关闭弹窗，不执行任何操作 |
| **仅同步可用车次（N 条）** | 忽略不可同步的，直接执行 |

> **设计考量：** 不在弹窗内提供「编辑」跳转，避免用户在执行前流失到编辑页面打断节奏。不满足条件的车次应在日常确认流程中处理完毕，同步是最后一步。

---

### 5.3 同步执行状态面板

用户确认后，弹窗切换为「执行中」视图：

- 顶部进度条：整体进度百分比
- 车次列表：逐条实时更新状态
  - `等待中` → 灰色点
  - `同步中` → 蓝色旋转图标
  - `成功` → 绿色勾
  - `失败` → 红色叉 + 失败原因缩略（如：超时、字段校验失败等）
- 执行过程中可显示当前正在处理的车次名称

**防误操作：** 执行过程中「关闭」按钮置灰，避免用户中断导致状态不一致。

---

### 5.4 同步结果汇总弹窗

执行完成后，弹窗切换为「结果汇总」视图，分三列展示：

```
┌──────────┬──────────┬──────────┐
│  成功 12 │  失败  2 │  跳过  4 │
└──────────┴──────────┴──────────┘
```

#### 成功区
- 车次列表，附同步完成时间戳
- 列表页面此时后台自动刷新这些车次的 `synced` 状态

#### 失败区（核心）
- 车次列表 + 具体失败原因（来自接口返回）
- 每条右侧提供操作按钮：
  - `重试`：单独对该车次重新发起同步请求
  - `编辑`：跳转打开该车次的编辑抽屉（EditDrawer），修完后支持「保存并重试同步」

#### 跳过区
- 展示因条件不满足被跳过的车次，仅供知晓，无操作按钮

#### 底部操作
| 按钮 | 行为 |
| :--- | :--- |
| **关闭** | 关闭弹窗，刷新列表 |
| **重试所有失败（N 条）** | 对失败区全部车次批量重试 |
| **导出失败记录** | 将失败车次及原因导出为 CSV，供线下排查 |

---

### 5.5 同步日志持久化（辅助）

同步结果除了在弹窗中展示外，还需要以「可追溯」方式持久化：

- **同步历史入口：** 工具栏增加「同步历史」按钮，或在页面底部 footer 区域展示最近一次同步的时间和结果摘要（如：「上次同步 14:32 · 成功 12 · 失败 2」）。
- **历史详情：** 点击后展示历史列表，每条记录包含：时间、操作人、同步总量、成功/失败数量，可下钻查看具体车次。

---

## 6. 与编辑流程的衔接

当用户从「失败详情」点击「编辑」进入 EditDrawer 时：

1. 抽屉顶部显示横幅提示：`该车次上次同步失败，原因：xxx`
2. 用户修改并保存后，抽屉底部提供「保存并立即同步」按钮
3. 单条同步结果以 Toast 形式反馈（成功 / 失败），无需再次打开汇总弹窗

---

## 7. 状态流转总览

```
未确认
  │ 用户确认 (Confirm)
  ▼
已确认 · 未同步
  │ 同步执行
  ▼
同步中（临时态）
  │
  ├─→ 成功 → 已确认 · 已同步
  │
  └─→ 失败 → 已确认 · 未同步（保持原态，附失败原因标记）
```

## 8. UI 元素汇总

| 元素 | 位置 | 说明 |
| :--- | :--- | :--- |
| 同步入口按钮 + 角标 | 工具栏右侧 | 角标显示可同步数量 |
| 预检弹窗（可/不可分区） | Modal 居中 | 用户同步前知情 |
| 执行进度面板 | 同一 Modal 切换 | 逐条实时状态 |
| 结果汇总（成功/失败/跳过） | 同一 Modal 切换 | 一次操作完整闭环 |
| 失败车次重试 + 编辑入口 | 结果面板内 | 快速修复链路 |
| 编辑抽屉内的同步失败提示 | EditDrawer 顶部横幅 | 上下文感知 |
| 保存并立即同步按钮 | EditDrawer 底部 | 修复后一步完成 |
| 同步历史摘要 | 页面底部 Footer | 持久化可追溯 |
