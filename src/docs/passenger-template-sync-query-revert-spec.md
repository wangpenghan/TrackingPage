# 客运模板同步状态管理补充方案

**版本：** v1.1（补充至同步流程规范 v1.0）  
**日期：** 2026-05-08  
**适用模块：** 客运模板 / 同步状态查询与回退

---

## 1. 补充背景

v1.0 方案覆盖了「同步前预检 → 执行 → 结果反馈」的正向流程，但缺少以下两项能力：

| 缺失项 | 问题 |
| :--- | :--- |
| **同步结果查询** | 用户无法在不触发同步的情况下，单独查看当前各车次的同步状态详情和历史记录 |
| **已同步回退为未同步** | 车次数据变更后，无法将已同步状态撤回，必须联系后台人工处理 |

---

## 2. 新增功能：同步状态查询

### 2.1 入口位置

在工具栏「同步客运模板」按钮旁增加「同步记录」入口：

```
[导入]  [导出]  [添加]  [同步记录]  [同步客运模板 ³]
```

「同步记录」使用次级样式（描边按钮），图标使用 `ClipboardList` 或 `History`。

---

### 2.2 同步记录面板设计

点击「同步记录」弹出侧边抽屉（右侧滑入，宽度 520px），内容分两个 Tab：

#### Tab A：本周期同步汇总

展示当前图号（或有效期内）所有车次的同步状态全览，支持按状态筛选和车次搜索。

```

├──────────────────────────────────────────────────────────┤
│  [全部 23]  [已同步 15]  [未同步 6]  [失败 2]            │
│  搜索车次 ________________                               │
├──────────────────────────────────────────────────────────┤
│  车次      状态      同步时间           操作              │
│  G473      已同步    05-08 14:32       [回退未同步]       │
│  D3710     已同步    05-08 14:32       [回退未同步]       │
│  G7181     未同步    —                 —                  │
│  G1001     失败      05-08 14:32       [查看原因] [重试]  │
│  ...                                                     │
├─────────────────────────────────��────────────────────────┤
│  [批量回退选中车次]                      [关闭]          │
└───────────────────────────────────────────���──────────────┘
```

**列说明：**

| 列 | 内容 |
| :--- | :--- |
| 车次 | 车次号 + 类型标签（始发/途径/终到） |
| 状态 | 已同步（绿）/ 未同步（橙）/ 失败（红）|
| 同步时间 | 最近一次同步操作的时间戳，未同步显示「—」 |
| 操作 | 根据状态显示不同操作（见下文） |

#### Tab B：历史同步批次记录

按每次点击「同步客运模板」为一个批次，记录完整历史。

```
┌──────────────────────────────────────────────────────────┐
│  批次时间          操作人   成功  失败  跳过              │
│  05-08 14:32      张三     12    2     4     [展开详情]   │
│  05-07 09:15      李四     18    0     3     [展开详情]   │
│  05-06 11:40      张三      9    1     2     [展开详情]   │
└──────────────────────────────────────────────────────────┘
```

展开详情时，下方展示该批次的每条车次记录及状态，失败的附带原因。

## 3. 新增功能：已同步回退为未同步

### 3.1 业务场景

| 场景 | 需要回退的原因 |
| :--- | :--- |
| 数据填写错误，同步后发现问题 | 回退后修改，再重新同步 |
| 计划变更，该车次本日不开行 | 回退后修改有效期或删除 |
| 误操作同步 | 撤回该次同步 |

### 3.2 回退规则

- **权限管控**：回退操作需有操作权限（建议调度长及以上）。
- **回退条件**：仅限「已同步」状态的车次，且距同步时间在 **24 小时**内可自助回退；超出时间需走审批流程。
- **回退效果**：`synced` 重置为 `false`，`confirmed` 保持 `true`（不需要重新确认，只需重新同步）。
- **连锁提醒**：回退时提示用户：「回退后该车次将从目标系统撤销，若已影响下游作业请确认后再操作。」

### 3.3 回退入口

提供三个层级的入口，覆盖不同操作习惯：

#### 入口 A：列表行内（悬浮显示）
已同步的车次行，鼠标悬浮时右侧操作区出现 `回退` 按钮（`RotateCcw` 图标）。

```
G473   已同步   14:32   [查看] [编辑] [回退] [删除]
```

#### 入口 B：同步记录面板（Tab A）
如上文 2.2 所示，已同步车次右侧有 `[回退未同步]` 操作。

#### 入口 C：批量回退
在同步记录面板底部，支持勾选多条已同步车次后点击「批量回退选中车次」。

---

### 3.4 回退确认交互

为防止误操作，回退操作需经过二次确认弹窗：

```
┌─────────────────────────────────────────────────┐
│  ⚠️  确认回退同步状态                            │
│                                                   │
│  车次 G473 将被标记为「未同步」。                 │
│                                                   │
│  · 已同步时间：2026-05-08 14:32                   │
│  · 回退后需重新执行同步操作                       │
│  · 若目标系统已依赖该数据，请谨慎操作             │
│                                                   │
│             [取消]  [确认回退]                    │
└─────────────────────────────────────────────────┘
```

---

### 3.5 批量回退交互

```
已选 3 条车次将被回退：G473、D3710、G7181

· 这些车次将被标记为「未同步」
· 若有车次已影响下游作业，请单独处理

          [取消]  [确认批量回退（3 条）]
```

## 4. 状态流转补充

在 v1.0 基础上，新增回退路径：

```
未确认
  │ 确认
  ▼
已确认 · 未同步
  │ 同步执行
  ▼
同步中
  │
  ├─→ 成功 → 已确认 · 已同步
  │              │
  │              │ 回退操作（新增）
  │              ▼
  │         已确认 · 未同步  ──→ 可再次同步
  │
  └─→ 失败 → 已确认 · 未同步（保持原态，附失败原因）
```

## 5. UI 元素汇总（增量）

| 元素 | 位置 | 说明 |
| :--- | :--- | :--- |
| 同步记录入口按钮 | 工具栏，同步按钮左侧 | 次级样式，不抢主操作焦点 |
| 同步状态查询 Tab | 同步记录侧边抽屉 | 全量车次状态一览，支持筛选和搜索 |
| 历史批次记录 Tab | 同步记录侧边抽屉 | 按批次记录，可下钻查看明细 |
| 单条回退按钮 | 列表行内悬浮操作区 | `RotateCcw` 图标，已同步才显示 |
| 单条回退按钮 | 同步记录面板 Tab A | 已同步行右侧操作 |
| 批量回退按钮 | 同步记录面板底部 | 多选后激活 |
| 回退二次确认弹窗 | Modal 居中 | 单条和批量各有对应文案 |
