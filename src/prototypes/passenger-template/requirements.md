#### 新的思路（生命周期管理）

客运模板应该是一个连续性的计划迭代过程，假如从某一个图作为起点，后面应该是一个完整的闭环流程，从一趟车什么时候启用、哪天收到变更调度命令，到最后一次停运这是一个完整的生命周期，客运模板应该是对这个生命周期的管理。

这个生命周期可能跨越了好多个调图周期，所谓的调图，就是在既有运行图的基础上，每年通常节假日、寒暑假期间做出大批量的运行图变更，实质也是一个大的调度命令下来，告诉车站哪些新增、哪些停运、哪些需要修改开行信息；而日常的调度命令只是对个别车进行区间、时间、上水、吸污作业变动的调整。

### 解决方案

#### 核心设计理念

- **从一次性配置转变为连续迭代的闭环流程**
- **车次生命周期管理**：启用 → 日常调度变更 → 调图批量变更 → 停运
- **区分变更类型**：日常调度（个别变更）vs 调图（批量变更）
- **版本历史保留**：每次变更都是一个新版本，完整记录历史

#### 页面布局设计

- **三栏式布局**：左侧车次列表 + 中间详情面板 + 右侧生命周期时间轴
- **时间轴视图**：清晰展示车次完整生命周期
- **变更对比**：直观对比相邻版本差异
- **卡片式设计**：避免水平拖动，信息分组展示
